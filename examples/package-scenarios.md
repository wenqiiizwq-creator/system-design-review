# 合成资料包行为用例

这些场景用于实际 Agent 正向验证；不是零漏检保证，也不使用真实项目资料。
命令行测试见 scripts/tests/test_validation.py；它只验证机械不变量。

| 场景 | 输入特点 | 应交付的行为 |
|---|---|---|
| 完整文档 | 需求写 Device，方案接口表写 Host | 文档内容路由；明确冲突，先修方案，不能以方案作为正确判据 |
| 只有需求 | 指定功能和预算，未选芯片 | 依据约束提出候选、收益代价、未知数据、新决策与确认草稿 |
| 只有图纸/器件资料 | 图中有三个通道，未说明用途 | 提取实现与用途候选，不能自动创建“三路必需”需求 |
| 部分文档 | 电源方案存在，接口附件缺失 | 按模块混合处理；引用附件建 missing 记录，不重复问已知电源范围 |
| 多版本/装配 | 原型保留接口，新版写删除；控制支路 DNP | 识别适用版本和选装，不把两种状态拼成同一默认设计 |
| 未知负载 | 无峰值电流或源能力 | 输出已知预算与 INSUFFICIENT，不把缺失算 0A 得到完整 PASS |
| 方案恢复逻辑 | 要求复位默认关，EN 内部上拉且 MCU 高阻 | 从器件条件核对状态实现；软件启动后关断不满足复位期目标 |
| 工程师纠正 | 明确撤销某条需求或选另一备选 | 保留旧版，修改受影响基线并复核，确认绑定新内容 |
| 中断恢复 | 已确认接口，尚缺电流 | 从台账续接，复用有效确认，只补缺失输入 |
| 原理图交接 | 已确认基线配当前图纸 | 交需求 ID/版本/角色/约束/未决，图纸差异不能反写成需求 |

## 无文档输入的最小预期产物

模块/电源树/接口角色/关键状态草稿，每条来源与观察置信度；不能推断的目标清单；
少量高价值问题；初步合理性检查和条件化优化；工程师未回复时 approvals=[]。
对话未答不妨碍完成其他分析，也不能伪造确认或签准出。
