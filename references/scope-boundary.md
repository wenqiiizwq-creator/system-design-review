# 边界、确认与交接

准出对象是系统方案基线。原理图可作提取证据；不签原理图进入 PCB，也不签实物性能。

| 域 | 本阶段判定 | 下游验证 |
|---|---|---|
| 需求/架构 | 目标一致、方案覆盖、资源与能力、取舍合理性 | 实际实现是否遵循受控基线 |
| 电源 | 轨/来源/负载、工况预算、保护/默认态/恢复、选型边界 | 逐脚/参数实现、PDN、PCB 压降、上电与热实测 |
| 接口 | 两端角色、电平、资源复用、带宽、连接器契约 | 逐针实现、阻抗/等长、SI、眼图 |
| 环境/保护 | 适用应力、保护与接地/隔离策略、热预算 | 布局位置、爬电、浪涌/EMC/热与完整鉴定 |
| 测试/供应 | 调试恢复/观测方案、明确的供应约束 | ICT、工艺/采购/装配与生产验收 |

## 四态与分级

PASS 有适用证据符合；FAIL 有适用证据不符合；INSUFFICIENT 适用但缺证；NA 有证据不适用。
A/B/C 表示证据置信度：A 为适用原始资料直接核实，B 为有依据但覆盖/条件较弱，C 为不足。
置信度与严重度独立；C 不得作 PASS/FAIL/NA。外部文档写了某结论不自动获得 A。

BLOCKER：损坏/安全/关键启动或核心功能不成立；Warning：其他必需功能或保证条件偏离；
Info：满足已知要求后的可选优化；观察为待核类别而非最低等级，单列潜在后果。
review_plan.critical 标记会阻断必需目标、物理边界或关键安全的项，不能为放行降级。
非关键 FAIL 可被具名责任方明确接受，仍保留 FAIL；关键缺证/缺陷不能靠确认变 PASS。

## 独立状态与准出

- 资料：已读/部分/未读/读取失败/缺失，注明适用性；
- 意图：草稿/待确认/指定版本和范围已确认；
- 技术：检查中/缺证/不符合/已闭环；
- 准出：可作原理图设计或审查基线 / 尚未准出并列条件。

允许：“系统方案基线可用于原理图设计/审查。”
未闭环：“方案草稿已形成，尚未准出；以下关键条件待关闭。”
禁止把“有条件冻结，须先关闭关键缺证”表述为已经冻结。
工程师确认是设计选择的确认，不证明技术通过；Agent 审查通过不能代替真实工程师回复。
确认和优化改变后按内容范围核验；JSON 摘要仅检测记录过期，不能认证人类身份/签名。

缺资料不阻止继续独立分析，但完整规格符合性和准出必须等待必要条件。
如正式改变要求，保留变更依据并审查新基线；不得用风险接受伪造原规范已满足。

## HANDOFF 与下游契约

每项带 required/state(OPEN/ACCEPTED/VERIFIED)/receivers/constraint/verification。
必需移交需被真实接收，约束和测试可执行；VERIFIED 还要验证证据。下游布局/测试未完成
可以 ACCEPTED，不在本阶段假称 VERIFIED。通用基线确认不等于具体风险接受或移交接收。

移交 schematic-review：基线版本/资料身份、需求 ID、模块/关键链路/工况、接口角色、
保护基线、待核项、HANDOFF、明确的未覆盖范围。校验双方字段映射，不假设同名 intent
JSON 可互换。没有对应 skill 时输出上述人读/机器契约，不要求安装无关工具。

原理图阶段以基线验证实现，发现需要换轨、改协议、换能力/选型或调整要求时回本阶段
决策闭环；纯位号/映射修改更新追踪即可。不能把图纸现状自动覆盖已确认目标。
