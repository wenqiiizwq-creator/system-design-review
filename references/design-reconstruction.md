# 从现有设计提取方案

用于缺少或局部缺少需求/方案的 A 模式。先产出“当前实现摘要 + 候选意图 + 待确认项”，
工程师不必先补写完整规格书。

## 提取次序与范围

1. 从全局框图、页面目录、BOM 和主芯片建立模块清单，区分目标板与参考板。
2. 提取电源来源/轨/负载，实际装配、使能/保护、上下电和外部回供路径。
3. 提取通信端点、Host/Device/主从角色、协议、速率、电平域、控制资源与对端附件。
4. 提取启动、时钟、复位、调试/烧录及核心功能链；记录软件依赖、默认态和故障恢复。
5. 核核心器件精确 MPN、封装/固定档/内部模型，读取相关工作区、默认态、保护模式、
   时序和复用限制；能力与应用条件进入 constraint，不自动成为 intent。
6. 根据历史决策与工程师对话补充“为什么如此选择”，标明推断与待确认。

可读取网表核实关键拓扑、DNP 和跨页关系；不要求此阶段完成全部引脚、ERC/WCA。
若只有 PDF，声明观察精度和连通性限制；发现明显实现问题可登记移交，不把未接线
或器件缺失当作需求本来不需要。型号冲突按候选分支保留，禁止从料号命名猜关键额定。

## 三层信息

| 记录 | 来源和权威 | 示例 |
|---|---|---|
| intent | 工程师确认的目标与取舍 | 设备需要连续输出 2A |
| implementation | 对应版本图纸/网表/BOM | 已画一个限流输出；阈值待核 |
| constraint | 精确型号/平台的适用规则 | 限流阈值有公差和温度条件 |
| estimate | 有模型的计算/假设 | 暂按并发负载估算，等待数据 |

“文档写了 10W”是有来源的主张，不等于 10W 已测量。图中没有 USB3 不能推出需求只要
USB2。已经装了三路也不能推出需求恰好三路。差异分别考虑：未实现需求、超范围实现、
文档过期、允许替代、装配选择或证据不足。

## 交给工程师的草稿

列模块、电源树、接口/资源、功能及状态图；每条标“观察事实/假设/待确认”和证据。
单列成本、环境、负载/并发、认证、寿命、不可改动部分等图纸无法充分表达的条件。
优先问会改变架构的问题，例如用途/带宽、连续与峰值负载、恢复策略、对端与装配版本。
先展示已完成的提取，不把资料中已有答案重新组成长问卷。

按 [design-capture.md](design-capture.md) 增量确认，随后进入 B 模式。
缺少确认时可以继续已知条件下的技术审查，但不得把候选意图签成最终需求。
