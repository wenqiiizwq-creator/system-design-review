# 交付模板

Markdown 和 design-intent.json 使用同一基线版本与 ID；原始资料保留，不覆盖。
只填有证据的内容，缺项显式未知；模板是交付结构，不是必须逐题问人的问卷。

## Design_Baseline_<项目>.md

- 状态摘要：基线/板卡/装配版本、资料范围、已确认条目、待答问题、下一步、当前准出状态。
- 资料与版本：清单/哈希/引用依赖、读取状态、当前/历史/备选、冲突与适用性。
- 需求表：ID｜原文来源｜原子条款/工况/单位/验收边界｜必需性｜确认状态。
- 当前实现与候选意图：模块/页面/位号范围｜观察事实｜用途推断｜约束｜证据｜待确认。
- 架构：信号流/控制流/电源和隔离域；框图与文字一致。
- 电源：轨/上游/电压/额定｜已知负载小计｜未计入项｜各工况预算/效率｜时序和依据。
- 接口资源：两端/角色/方向视角｜协议/速率/电平｜主控资源/互斥｜线缆/附件/软件约束。
- 选型与装配：精确 MPN/封装/版本/内部模型｜能力和条件｜已选/DNP备选｜保护基线。
- 状态表：状态｜进入条件｜控制/观测｜输出默认态｜退出/故障/恢复｜需求和证据。
- 优化与决策：目标｜当前方案/备选比较｜收益/代价/风险/未知｜推荐｜工程师选择。
- 开放问题与确认：ID/影响/负责人/补证方式；版本、条目范围、真实回复定位。

## Design_Review_<项目>.md

```markdown
# 系统方案审查：项目与版本

## 结论与范围
资料完整性 / 意图确认 / 技术审查 / 方案准出分别表述；列限制和阻断条件。

## 需求与对象覆盖
需求 ID→方案落点→验收方式→检查 ID；模块/接口/器件/状态/电源对象的检查映射。

## 逐项结果
计划 ID｜层/对象｜适用性｜结果｜严重度/潜在后果｜置信度｜工况｜证据。

## 缺陷、待核及优化
位置与当前事实；被违反条款；条件与后果；【原】→【改】→【理】；
备选收益/代价；受影响模块/参数；改后复算和可测量复验标准。

## 修订与工程师确认
历史 ID｜处理/撤回原因｜复验证据｜版本/确认范围｜状态。

## 下游移交
ID｜required/state｜receivers｜constraint｜verification｜真实接收记录。

## 机器检查
输入版本/摘要、命令、输出文件和结果；机械通过与技术判断的边界。
```

引用格式：datasheet 名称/版本/页表；平台规则位置/适用版本；对话实际消息定位；
网络补取的 URL/获取日期。参数计算列公式、取值来源和工作条件，不能只写“已计算”。
最终对工程师突出待其决定的内容，避免把工具内部字段堆进提问中。
