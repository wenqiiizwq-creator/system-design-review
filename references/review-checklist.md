# 系统级方案审查检查表（模式 B）

执行序 = 编号。每项产出四态结果 + 证据置信度 + 证据链（文件:页码/表号 或 对话轮次）。

## 0. 意图对齐

从基线/材料提取 7 个意图块并成文留痕。缺材料标 INSUFFICIENT，报告头部声明
“规格符合性判定受限”——不得补全臆测。意图清单错了，下游结论会连锁错。

## 1. 需求覆盖矩阵

每条需求 → 方案章节 → 验证方式 → 状态。缺覆盖、自相矛盾 = FAIL；“已覆盖”必须
指到具体章节。`scripts/check_requirements.py` 做机械闭合检查，语义核对仍靠逐条读。

## 2. 整体架构

信号流是否端到端闭环；电源/地策略（单点/星型/隔离域）与信号域一致；主从与数据
路径无隐藏单点；扩展性/兼容性（调试与预留）。架构图与文字方案互相印证。

## 3. 电源树审计

逐轨三问：谁驱动（0R/跳线要追到真实源）/ 谁负载 / 电平对不对。负载电流求和，
裕量 ≥20–30%（拿不到负载电流标 INSUFFICIENT 索取，不许跳过）。上电时序与掉电
顺序有依据；跨轨上拉/倒灌候选明确；输入保护、限流、反接、热插拔浪涌有方案。
`scripts/check_power_tree.py` 做机械求和与裕量检查。

## 4. 外设与接口分配

引脚复用冲突（SoC 引脚功能互斥、电平域）；总线冲突与寻址；IO 域电平一致；
带宽/速率与主控能力匹配；连接器 pin 定义完整（电源、地、信号、保留脚）；
复位/启动配置脚不受外围拖偏。

## 5. 关键器件选型与降额

MPN 身份明确；工作点 vs Abs Max / 推荐工作区；降额策略逐项适用（电压/电流/温度/
功率）；替代料电气与封装兼容。生命周期与单一来源列为供应链 HANDOFF，不算本 skill
的冻结结论。

## 6. 功能方案与关键链路

每条关键链路端到端走通（检测→处理→执行 / 通信收发 / 保护反馈）；时钟/复位/启动
链有单一来源；失效安全（默认态、看门狗、掉电行为）明确。

## 7. 环境/可靠性/EMC 前置

只判方案可定的：防护器件与泄放路径选型、SWaP 与热预算估算、隔离与接地策略。
需要布局或实测的写入 HANDOFF，不得冒充冻结结论。

## 8. 可测可维护

调试/烧录接口、关键观测测试点、版本与序列号机制已在方案中规划。

## 9. 输出报告 + 修订闭环

报告模板见 `references/report-template.md`。整改后复跑受影响检查项，历史意见逐条
给复验证据；BLOCKER 清零、Warning 关闭或书面接受、关键 INSUFFICIENT 关闭或接受、
HANDOFF 形成可执行约束后，才签“系统方案可冻结并进入原理图设计”。

每层哪些方案可判、哪些移交、哪些不判，见 `references/scope-boundary.md` 边界矩阵。
